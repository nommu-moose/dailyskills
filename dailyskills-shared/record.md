# Record rules

Not a skill. A study skill loads this when it runs. The record is theirs. Resume it. Do not overwrite it, and do not open a second record because this one looks thin.

The folder is one they name. Do not search the disk for it. If they name none, do the sitting and save nothing, and say that nothing was saved. An empty or missing record is not a reason to wait, and it is not evidence that they are behind.

When they name a folder, use these files. Create a missing file with its heading only, and with no invented claims. If a file exists, edit it in place.

| File | Holds |
| --- | --- |
| `INDEX.md` | What this record is, and the subject if they have named one. |
| `POSITION.md` | Where they are, against the material or the skeleton. |
| `CLAIMS.md` | What is taken to be known. |
| `PACE.md` | Behind, on, or ahead, and the reason. |
| `PITFALLS.md` | Habits they repeat. |
| `LOG.md` | One short entry per sitting. |

Do not replace a file with a fresh one.

`study` interprets the record: where they should be, whether to hurry, and whether they are ahead. Hurry by naming a specific cut. Ahead means say so and offer widening, not invented work. The other skills add a pace line only when the record shows they are materially off. They do not rejudge the whole position.

A claim says whether the user said it or the agent inferred it. Thin evidence stays labelled thin. A later sitting that no longer trusts a claim downgrades it and says why. It does not silently replace the claim, and it does not delete it.

A log entry names the skill, what was worked, and what changed in the record. It is not a transcript. Record a pitfall when it repeats. Remove a pitfall only when they say it is gone.
